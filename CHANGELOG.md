## v1.11.39 (tag `v1.11.39`), 2026-11-15 (911 listening test: v11 · 911 p3 with 3-chamber side boxes)

* New, **non-default** 911 option **Sound v11 · 911 p3** (`?p997=p3`, also `v11.p3`; the slot freed in v1.11.38, so old p3 links now open this): p1 with a different side box on each bank, laid out after a cut-away press photo of the OEM 997 muffler supplied by the owner: three chambers in a row (0.12 / 0.16 / 0.12 m, 11 × the 57 mm pipe area, about 11 L), two perforated baffle walls (3 % open area, 4 mm holes, 1.5 mm plate), a 52 mm tube through each baffle, a small 18 mm equalising tube through baffle 1, steel-wool packing in the rear end-cap chamber and a 58 mm outlet. **Every box dimension is an estimate**: no factory figures exist, and the layout comes from the photo and forum descriptions (3 chambers, perforated baffle, pipes through the baffles). Flared tube ends are not modelled.
* New generic block `par` (Python and JS): N parallel paths (tubes, a perforated baffle's holes lumped as one short neck, a small tube) from one volume into the next chamber. Parameters only; no per-car code.
* **Listening test, with one check failure.** Better than p1 from 3,500 to 7,000 rpm: the cabin 3rd order now roughly holds (rel. 3,500 rpm at 4,500 / 5,500 / 6,500: p1 −13.5 / −15.1 / −18.3 dB, p3 +2.0 / −6.8 / −4.5; recordings, per clip: about −7 / −1 / +6), and the full-throttle level outside rises with rpm instead of falling. 2–8 kHz stays below the recordings relative to the 3rd order (not harsh; far below p2). **Fails:** a deep dip in the 3rd order at 2,000–3,000 rpm (cabin about −17 dB vs p1 at 2,500) with the 6th order about 18 dB louder, so order 6 sits 4–19 dB above order 3 there, against about −12 dB in the recordings. Outside, the 3rd order rises a few dB at 4,500–6,000 rpm where the recordings fall a few dB.
* p1 stays the default; p2 is unchanged. The GT350, Cadillac, BRM and 911 p1 / p2 sounds are bit-identical to v1.11.38. JS matches Python on p3 (order deltas within about 1 dB). CPU about +15 % over p1 (still below p2).

## v1.11.37 (tag `v1.11.37`), 2026-11-15 (911 listening test: v11 · 911 p3 with intake runners)

* New, **non-default** 911 option **Sound v11 · 911 p3** (`?p997=p3`, also `v11.p3`): p1 plus a generic intake-runner block, one 1D travelling-wave pipe per cylinder from the intake valve to its bank plenum. Runner length 0.216 m (owner-supplied M97.01 figure; no public source found to confirm it). Runner diameter 45 mm is an **estimate** (two 40.2 mm intake valves; no factory runner ID found) and the 4.5 L plenum volume is a **guess** (unchanged from p1). The 76 mm throttle body is unchanged.
* **This is a listening test, and it fails the scorecard checks.** It improves the cabin 3rd-order shape (rel. 3,500 rpm at 4,500 / 5,500 / 6,500 rpm: real −3.4 / +4.2 / −5.7 dB; p1 −13.4 / −15.1 / −18.3; p3 −11.5 / −9.9 / −3.5; shape error 41.9 → 24.4 dB), but the 5–6k rise is still missing, and it **fails** two checks: a loud cabin **4.5-order tone near 4,500 rpm**, about 24 dB above the real recording (narrow-tone rule: ≤ 6 dB), and **10–16 dB more energy between 2 and 8 kHz** at 3,500–4,500 rpm. The 997 workshop manual also describes perforated resonance chambers in the distributors that damp intake resonance at 5,000–6,000 rpm, which the runner block does not model.
* **p1 stays the default; p2 is unchanged.** The runner block is generic (parameters `int_run`, `int_run_l`, `int_run_d`, `int_run_nseg`, `int_run_attach`; no per-car code), off unless a set enables it. The GT350, Cadillac, BRM and 911 p1 / p2 sounds are bit-identical to v1.11.36. JS matches the Python v8phys kernel on the p3 order curves (order 3 within about 1 dB). CPU: about +10 % on the 911 (22 → 28 waveguide pipes).
* Sound development and tuning guidelines are now in the repo: [SOUND_GUIDELINES.md](SOUND_GUIDELINES.md).

## v1.11.36 (tag `v1.11.36`), 2026-11-15 (sound model v11 across all cars; generic physics)

* One version nomenclature for the sound model on every car: **sound model v11** (the shared physics kernel) plus a per-car parameter-set iteration, shown as **v11 · 911 p1**, **v11 · BRM p11**, and so on. The BRM's v9.1–v9.11 history maps onto **v11 · BRM p1–p11**, with p11 the default. The 911's just-shipped v10.1 / v10.2 labels become **v11 · 911 p1** (default) and **v11 · 911 p2**. The GT350 and Cadillac v9p defaults become **v11 · GT350 p1** and **v11 · Cadillac p1**. Earlier v1–v4 kernels stay in the V8 Sound menu under their old names. Old labels and query values alias to the new names (see the mapping table in the release notes / info page).
* The physics model is now fully generic: a car is only a parameter set, with no `car=="p997"` branches. VarioCam Plus is a generic variable-cam block (a phase map vs rpm/load and a two-step lift switch with thresholds), enabled by parameters. The intake flap / plenum-shrink, `int_res` settle, muffler topology (`muf` list, `muf_as_cavity`, `cat_early`) and `tick_alpha` are all parameters. The JS `engineKey` maps and the `phys_v10*` overlays are ordinary per-car parameter sets (`p1` / `p2`). Output is bit-identical to v1.11.35 for every car and every picker option.
